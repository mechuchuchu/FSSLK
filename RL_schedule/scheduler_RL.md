# 실험 설계: 시계열 기반 RL을 이용한 이기종 분산 작업 스케줄링

## 1. 연구 개요

### 1.1 연구 목표

본 연구는 서로 다른 계산 성능과 네트워크 조건을 가진 여러 worker에서 작업을 실행할 때, 강화학습(Reinforcement Learning, RL)이 작업 대기, 중복 할당 및 재시도 시점을 동적으로 결정하여 전체 실행 시간을 단축할 수 있는지 검증한다.

초기에는 고정된 랜덤 벡터 데이터를 외우는 작은 MLP(Multi-Layer Perceptron)를 사용한다. 이를 통해 복잡한 신경망 구조와 대규모 데이터셋 없이도 분산 실행, gradient 집계, 무한 대기, 중복 실행 및 장애 복구를 실험할 수 있다.

핵심 아이디어는 스케줄러가 현재 상태 하나만 보는 것이 아니라, worker의 과거 처리 속도, 진행률, heartbeat, 네트워크 지연 등의 시간 변화를 함께 관찰하도록 만드는 것이다.

연구의 중심 질문은 다음과 같다.

> **과거의 실행 기록을 학습한 RL 스케줄러는 언제 기다리고, 언제 작업을 복제하며, 언제 재시도해야 하는지 더 잘 판단하여 분산 작업의 완료 시간을 줄일 수 있는가?**

### 1.2 연구 가설

- H1. 처리량에 비례해 작업을 배분하는 것만으로는 동적으로 변화하는 네트워크와 worker 장애에 충분히 대응하기 어렵다.
- H2. 시계열 정보를 사용하는 RL 정책은 현재 상태만 사용하는 정책보다 worker의 성능 변화와 작업 정체를 더 잘 구별할 수 있다.
- H3. 적응형 대기 및 중복 실행 정책은 고정 timeout보다 불필요한 재시도와 전체 작업 완료 시간을 줄일 수 있다.
- H4. 이러한 효과는 네트워크와 worker 상태가 시간에 따라 변하는 환경에서 더 뚜렷하게 나타난다.

위 가설은 실험으로 검증할 대상이며, RL이 휴리스틱보다 항상 우수하다고 가정하지 않는다.

## 2. 전체 연구 단계

연구는 다음 순서로 진행한다.

1. 단일 프로세스에서 랜덤 벡터를 외우는 MLP 구현
2. 작업을 여러 worker에 분배하고 결과를 정확하게 집계
3. 처리량이 다른 worker를 이용한 스케줄링
4. 시계열 기반 RL로 WAIT와 DUPLICATE 결정
5. 무한 대기, 네트워크 단절, 결과 유실 및 늦은 응답 추가
6. 악성 또는 잘못된 결과를 보내는 worker 추가
7. 실제 텐서 연산과 소규모 분산 환경에서 검증

각 단계에서 이전 단계의 정확성과 성능이 유지되는지 확인한 다음 복잡도를 높인다.

## 3. 1단계: 랜덤 벡터 암기용 MLP

### 3.1 데이터 구성

고정된 난수 시드로 입력 벡터와 목표 벡터를 생성한다.

\[
D=\{(x_i,y_i)\}_{i=1}^{N}
\]

여기서 \(x_i\)와 \(y_i\)는 무작위로 생성한 벡터이며, 학습이 끝나도 데이터는 변경하지 않는다.

예시 설정은 다음과 같다.

| 항목 | 초기 설정 예시 |
|---|---|
| 데이터 개수 | 1,024개 |
| 입력 차원 | 32 |
| 출력 차원 | 16 |
| 모델 | 작은 완전연결 MLP |
| 손실 함수 | Mean Squared Error |
| 데이터 | 고정된 난수 입력·목표 쌍 |
| 모델 초기화 | 고정 시드 |
| 최적화 | SGD 또는 Adam |

이 수치는 시작점일 뿐이다. 먼저 단일 프로세스에서 충분히 낮은 학습 손실에 도달할 수 있는지 확인한 후, 필요에 따라 모델 크기와 데이터 개수를 조정한다.

이 실험의 목적은 일반화 성능을 높이는 것이 아니라, 모델이 고정된 학습 데이터를 암기하는 과정을 반복 가능하게 만드는 것이다.

### 3.2 단일 프로세스 기준선

먼저 하나의 프로세스에서 학습시켜 다음 값을 기록한다.

- 학습 손실과 손실 감소 속도
- 목표 손실까지 걸린 시간
- 각 학습 step의 실행 시간
- 학습 시드 및 모델 초기화 조건
- 학습 결과와 gradient의 재현성

이 결과를 분산 실행의 기준선으로 사용한다.

### 3.3 분산 실행 방식

전체 데이터를 여러 shard로 나누고, 각 worker는 하나의 shard에 대한 gradient를 계산한다.

\[
g_v=\sum_{j=1}^{K}g_{v,j}
\]

여기서 \(g_{v,j}\)는 모델 버전 \(v\)에서 계산한 shard \(j\)의 gradient 기여분이다. 실제 구현에서는 각 shard의 크기에 따른 가중치를 반영하여 전체 데이터의 gradient와 일치하도록 집계한다.

모든 필수 shard의 결과가 확보되면 optimizer를 한 번 실행한다.

이 구조에서는 느린 shard를 다른 worker에서 복제할 수 있지만, **동일한 shard의 gradient를 두 번 합산해서는 안 된다.** 복제된 작업 중 검증된 결과 하나만 채택하고 나머지는 무시한다.

따라서 스케줄러는 작업 실행 순서와 배정은 자유롭게 조절하되, 학습 알고리즘의 의미와 gradient 집계의 정확성은 유지해야 한다.

## 4. 2단계: worker 및 네트워크 시뮬레이터

초기에는 실제 GPU를 연결하기보다 Python 시뮬레이터에서 다양한 조건을 빠르게 재현한다.

각 worker에는 다음 속성을 부여한다.

- 계산 처리량
- RTT와 유효 대역폭
- 작업별 실행 시간
- heartbeat 주기
- 작업 진행률
- 일시적 또는 영구적 장애 확률

예시 환경은 다음과 같다.

| Worker | 상대 처리량 | RTT | 특성 |
|---|---:|---:|---|
| A | 100 | 5 ms | 빠르고 안정적 |
| B | 60 | 20 ms | 중간 성능 |
| C | 20 | 100 ms | 느리고 불안정 |

위 값은 시뮬레이션용 예시이며 측정 결과가 아니다.

시뮬레이터는 계산 시간, 통신 시간, worker 정체 및 결과 도착 시간을 별도로 모델링해야 한다. 초기에는 결과를 수학적으로 계산해 실제 MLP 없이도 스케줄러의 결정을 비교할 수 있게 한다.

이후 실제 MLP의 shard별 gradient 계산 시간을 측정하여 시뮬레이터의 처리 시간 분포를 보정한다.

## 5. 3단계: 시계열 기반 RL 스케줄러

### 5.1 문제 정의

이 문제는 현재 상태를 관찰해 즉시 작업을 배정하는 것만으로 설명하기 어렵다. 스케줄러는 작업이 지연되는 동안 상태를 반복적으로 관찰하고, 언제 다시 판단할지도 결정해야 한다.

따라서 이 문제를 부분 관측되는 동적 의사결정 문제로 정의한다. 의사결정 사이의 시간 간격이 달라질 수 있으므로 필요하면 semi-Markov decision process(SMDP) 형태로 모델링한다.

### 5.2 상태(State)

에이전트는 worker별 현재 값과 최근 관측 기록을 사용한다.

- 최근 처리량과 처리량 변화율
- 작업 경과 시간과 예상 완료 시간
- 작업 진행률 및 진행률 변화
- heartbeat 도착 시각과 간격
- RTT, 대역폭 및 통신 실패 기록
- 대기 작업 수와 실행 중인 작업 수
- 재시도 횟수 및 이전 작업의 완료 시간
- 현재 모델 버전과 미완료 shard 목록

예를 들어 다음과 같은 관측을 고려한다.

| 시점 | 처리량 | 진행률 | RTT | Heartbeat |
|---|---:|---:|---:|---|
| \(t-3\) | 100 | 50% | 20 ms | 정상 |
| \(t-2\) | 95 | 60% | 25 ms | 정상 |
| \(t-1\) | 85 | 68% | 45 ms | 정상 |
| \(t\) | 70 | 69% | 90 ms | 정상 |

현재 heartbeat는 정상적으로 도착하고 있지만 처리량이 감소하고 진행률이 정체되고 있다. 스케줄러가 이 패턴을 학습해 단순한 순간 지연과 실제 정체 가능성을 구별하는 것이 목표다.

### 5.3 행동(Action)

첫 버전에서는 행동을 두 가지로 제한한다.

**WAIT(\(\Delta t\))**

현재 작업을 유지하면서 일정 시간 뒤 다시 관찰한다. 대기 시간은 예를 들어 짧음·중간·김의 세 가지로 이산화할 수 있다.

**DUPLICATE(worker)**

현재 작업을 다른 worker에 복제하여 실행한다. 기존 작업은 계속 진행될 수 있으며, 두 결과 중 유효한 하나만 채택한다.

이후 확장 단계에서 다음 행동을 추가한다.

- RETRY: 기존 작업의 실패가 확인되었거나 재시도가 필요할 때 다른 worker에 다시 배정
- CANCEL_REQUEST: 기존 작업에 취소를 요청
- CHANGE_PRIORITY: 특정 작업의 우선순위를 조정

취소 요청이 기존 계산을 즉시 멈춘다고 가정하지 않는다.

### 5.4 RL 모델

초기 버전에서는 최근 \(k\)개 시점의 관측 벡터를 이어 붙인 뒤 작은 MLP 정책망에 입력한다.

\[
s_t=[x_t,x_{t-1},\ldots,x_{t-k+1}]
\]

이후 비교 실험에서 LSTM 또는 GRU 기반 정책을 추가한다. Transformer는 더 긴 기록이 유의미한 이득을 제공하는지 확인한 다음 검토한다.

PPO 등을 학습 알고리즘의 후보로 사용할 수 있으나, 특정 알고리즘이 항상 최선이라고 가정하지 않는다.

### 5.5 보상(Reward)

최종 목표는 불필요한 계산을 줄이면서 모든 필수 결과를 정확하게 확보하는 데 걸리는 시간을 단축하는 것이다.

\[
\min_{\pi}\ \mathbb{E}[T_{\mathrm{makespan}}]
\]

시간 경과, 통신량, 중복 계산량을 반영한 보상은 다음 형태에서 시작한다.

\[
r_t=-\Delta t-\lambda C_{\mathrm{network}}
-\mu C_{\mathrm{duplicate}}
\]

모든 필수 작업이 완료되고 결과가 검증되면 에피소드가 성공적으로 종료된다. 필수 작업이 누락되거나 유효하지 않은 결과를 채택한 경우에는 실패로 처리한다.

가중치 \(\lambda,\mu\)는 실험에서 조정하며, 보상값뿐 아니라 실제 완료 시간과 계산량을 따로 기록한다.

## 6. 4단계: 장애 및 비정상 상황 추가

장애는 한꺼번에 추가하지 않고 단계적으로 구성한다.

### A. 느린 worker

계산 시간이 길지만 정상적으로 진행되는 worker를 만든다. 이 상황에서는 성급하게 복제하기보다 기다리는 것이 유리할 수 있다.

### B. 작업 무한 대기

작업을 시작한 worker가 진행률을 갱신하지 않고 결과도 반환하지 않도록 한다. scheduler는 정체를 감지하고 대기 또는 복제를 선택해야 한다.

### C. Heartbeat와 진행률의 불일치

heartbeat는 정상적으로 전달되지만 실제 작업은 진전되지 않는 상황이다. heartbeat만으로 정상 여부를 판단하는 정책과 진행률까지 관찰하는 정책을 비교한다.

### D. 결과 유실

worker는 계산을 완료했지만 네트워크 오류로 결과 메시지가 도착하지 않는다. 이 경우 재계산이 실제로 필요한지 판단하는 문제가 생긴다.

### E. 늦은 응답

timeout 이후 새 worker에서 복제 작업을 시작했지만, 원래 worker가 뒤늦게 결과를 반환한다. 동일한 작업이 두 번 반영되지 않도록 결과 검증과 중복 완료 방지 로직을 시험한다.

### F. Worker 이탈 및 재접속

worker가 계산 중 연결을 끊었다가 다시 접속한다. 재접속 후 과거 작업을 계속 실행하거나 기존 결과를 반환할 수 있도록 설정해 복구 동작을 검증한다.

### G. 악성 또는 잘못된 worker

마지막 단계에서 잘못된 gradient, 진행률 조작, 누락된 데이터에 기반한 결과 등을 반환하도록 한다.

이 단계에서는 스케줄링과 결과 검증을 구분한다. RL 스케줄러가 응답 시간을 보고 이상 징후를 발견할 수는 있지만, 결과가 수학적으로 유효한지를 모두 알아서 판단할 수 있다고 가정하지 않는다. 별도의 검증 로직을 적용하고, 검증되지 않은 gradient는 모델에 반영하지 않는다.

## 7. 비교 대상

다음 정책을 같은 작업과 장애 시나리오에서 비교한다.

| 정책 | 특징 |
|---|---|
| Equal Split | worker별 동일 작업량 |
| Proportional | 최근 처리량에 비례한 배분 |
| Fixed Timeout | 일정 시간 이후 재시도 |
| Adaptive Heuristic | 최근 처리량과 예상 완료 시간에 따라 대기 및 복제 |
| Instantaneous RL | 현재 상태만 입력받는 RL |
| History-aware RL | 최근 여러 시점의 관측을 사용하는 RL |

중복 실행과 재시도 기능은 비교 대상에 가능한 한 동일하게 제공한다. 그렇지 않으면 RL이 더 많은 행동을 수행할 수 있다는 이유만으로 유리해지는 문제가 발생한다.

가장 중요한 비교는 다음 두 가지다.

1. Adaptive Heuristic 대 History-aware RL
2. Instantaneous RL 대 History-aware RL

이를 통해 RL 자체의 효과와 과거 정보 사용의 효과를 분리해서 분석한다.

## 8. 평가 지표

### 주요 지표

- **Makespan:** 모든 필수 결과를 확보하고 완료 상태로 확정하기까지 걸린 시간
- **Time-to-Target-Loss:** MLP가 사전에 정한 학습 손실에 도달할 때까지 걸린 시간
- **Completion Rate:** 제한 시간 안에 유효한 결과를 확보한 작업 비율
- **Recovery Time:** 장애 발생 이후 작업 진행이 복구될 때까지 걸린 시간

### 보조 지표

- 중복 계산량과 중복 실행 시간
- 불필요한 재시도 횟수
- worker별 유휴 시간
- 실제 전송 데이터량과 통신 대기 시간
- 늦게 도착한 결과의 수
- gradient 오차와 결과 정합성 위반 횟수
- RL 추론 및 제어에 소요된 오버헤드

단순한 텐서 작업 단계에서는 makespan을 중심으로 평가한다. MLP 학습 단계에서는 동일한 손실 기준에 도달한 시간과 단일 프로세스 기준 gradient와의 차이를 함께 측정한다.

## 9. 실험 절차

### 1단계: 단일 MLP 구현

고정된 랜덤 데이터셋을 생성하고, 단일 프로세스에서 안정적으로 암기 학습을 수행하는지 검증한다.

### 2단계: 정확한 분산 gradient 계산

데이터를 shard로 나누어 worker별 gradient를 계산하고 집계한다. 결과가 단일 프로세스 기준과 일치하는지 확인한다.

### 3단계: 스케줄러 기준선 구축

Equal Split, Proportional, Fixed Timeout, Adaptive Heuristic을 구현한다.

### 4단계: 시계열 RL 학습

시뮬레이터에서 WAIT와 DUPLICATE 행동을 학습시킨다. 학습 환경과 평가 환경을 분리하여 미관측 조건에서도 성능을 확인한다.

### 5단계: 장애 시나리오 확장

무한 대기, 결과 유실, 늦은 응답, worker 이탈을 하나씩 추가한다. 이후 복합 장애와 악성 worker를 시험한다.

### 6단계: 실제 텐서 연산 검증

실제 worker 프로세스에서 텐서 연산을 수행하고, 모델 버전 및 작업 ID를 이용해 결과가 중복 집계되지 않는지 검사한다.

### 7단계: 분산학습으로 확장

앞선 실험에서 스케줄링 성능과 정확성이 검증된 경우에만 ResNet 등 실제 모델로 확장한다.

## 10. 성공 기준

RL의 성공 여부는 GPU 사용률만으로 판단하지 않는다. 다음 조건을 종합적으로 확인한다.

1. 미관측 장애 시나리오에서도 makespan이 기준 정책보다 줄어드는가?
2. 동일한 최종 학습 결과와 gradient 정확성을 유지하는가?
3. 중복 실행과 재시도로 인한 추가 비용을 포함해도 이득이 남는가?
4. 시계열 기반 정책이 현재 상태 기반 정책보다 유의미하게 나은가?
5. RL이 적응형 휴리스틱보다 나은 상황과 그렇지 않은 상황을 구분할 수 있는가?

실험은 여러 난수 시드와 다양한 worker 조건에서 반복한다. 평균 성능뿐 아니라 변동성, 신뢰구간, 최악의 경우도 함께 보고한다.

## 11. 예상되는 한계

랜덤 벡터를 외우는 MLP는 스케줄링 실험을 단순화하기 위한 테스트 환경이다. 이 단계에서 성능이 좋아도 곧바로 분산 신경망 학습의 수렴이 개선되었다고 결론 내릴 수는 없다.

실제 분산학습에서는 gradient의 오래된 정도, optimizer 상태, 모델 수렴 안정성, 데이터 분포 차이 등 추가 문제가 발생한다. 따라서 독립적인 텐서 작업과 분산 학습을 구분하고 단계별로 검증한다.

또한 이 시뮬레이터는 네트워크와 worker의 실제 상태를 완벽하게 관찰할 수 없도록 설계해야 한다. 그렇지 않으면 RL은 불확실한 환경에서 판단하는 법을 배우지 않고, 시뮬레이터가 제공하는 정답에 가까운 신호만 이용하게 될 수 있다.

## 결론

본 연구는 고정된 랜덤 벡터를 암기하는 작은 MLP를 출발점으로 삼아, 시계열 정보를 기반으로 작업을 기다릴지 복제할지 판단하는 RL 스케줄러를 개발한다.

핵심은 **작업이 언제 끝날지 불확실한 상황에서 대기 비용과 중복 계산 비용을 비교하고, 과거의 시간 패턴을 이용해 적절한 의사결정 시점을 학습하는 것**이다.

이후 무한 대기, 네트워크 장애, 늦은 결과, 악성 worker 등을 점진적으로 추가함으로써, 시계열 기반 RL이 단순한 작업 배분을 넘어 실제 분산 환경의 불확실성과 장애에 얼마나 잘 대응하는지 검증한다.
