# FSSLK 작업 기록 — 2026-10-23

## 오늘 한 일

### CPU 분산 실행 프로토타입 구현

- TCP 기반 Coordinator와 CPU Worker를 구현했다.
- Worker가 Coordinator에 등록하고 주기적으로 heartbeat를 보낸다.
- `status` 명령으로 Worker ID, 장치 유형, CPU 코어 수, heartbeat 상태를 조회할 수 있다.
- Coordinator가 작은 PyTorch CPU 텐서의 원소를 Worker들에게 나눠 보내고, 부분합을 모아 최종 결과를 계산한다.
- Docker Compose 설정으로 Coordinator 하나와 Worker 여러 개를 실행할 수 있도록 구성했다.
- 실행 방법과 현재 제한 사항을 `README.md`에 기록했다.

관련 파일:

- `fsslk/coordinator.py`

- `fsslk/protocol.py`
- `fsslk/__main__.py`
- `Dockerfile`

## 실행 및 검증

Docker Compose로 CPU 전용 PyTorch 이미지를 빌드하고 Coordinator와 Worker 두 개를 실행했다.

```bash
docker compose up --build --scale worker=2 -d
```

두 Worker가 `active`로 등록된 것을 확인했다. 16개 원소를 분산 합산한 결과는 기대값과 일치했다.

```text
Distributed result: 120
Expected result: 120
Workers: 2개
```

이후 Worker 하나를 중지했다. 상태 조회에 남은 Worker 하나가 표시됐고, 17개 원소의 분산 합산 결과도 기대값과 일치했다. Worker를 다시 시작한 뒤 두 Worker의 재등록과 작업 재실행도 확인했다.

```text
Distributed result: 136
Expected result: 136
```

## 현재 제한 사항

- Worker 작업 중 연결이 끊기면 다른 Worker에 자동 재할당하지 않는다. 현재 Coordinator는 작업 응답을 최대 30초 기다린 뒤 실패 처리한다.
- 텐서 값은 작은 테스트를 위한 JSON 숫자 배열로 전송한다. 대규모 텐서용 전송 형식과 최적화는 구현하지 않았다.
- 인증, 암호화, WAN 상태 측정, 적응형 스케줄링은 아직 구현하지 않았다.
- 컨테이너 로그와 CLI에서 PyTorch의 NumPy 미설치 경고가 보이지만, 현재 합산 작업은 정상 동작했다.

Docker 클러스터는 작업 기록 시점에 실행 중이다. 종료할 때는 다음 명령을 사용한다.

```bash
docker compose down
```
